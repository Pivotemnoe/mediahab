# UI Этап 12N — Усиление и выпуск закрытого пилота

## Статус

Выпущено на production-цель закрытого пилота 14.08.2026 из коммита `8caebf06c18b9a9eb6a5988e623d889bdced6d9d` под неизменяемым тегом `pilot-20260814-phase12n`. Локальный гейт, GitHub Actions, свежая резервная копия, замена только приложения и автоматические послерелизные проверки пройдены. Релиз готов для приглашённых браузерных тестировщиков; проверка микрофона, фона и сна на физическом iPhone остаётся ручным гейтом перед расширением группы.

## Цель

Превратить локально принятую очистку первого входа в честный закрытый пилот:

`владелец создаёт одноразовое приглашение -> тестировщик один раз регистрируется -> обучение -> диктовка/блокнот -> ручная проверка и экспорт -> восстанавливаемый доступ через владельца`

Production не переключается, пока не пройдены локальные проверки, GitHub-гейт, свежая резервная копия, проверка миграции и безопасная замена только приложения.

## Объём и продуктовые решения

- Свободная регистрация в production закрыта. Нужна одноразовая привязанная к почте ссылка с ограниченным сроком, которую создаёт серверная команда владельца.
- Получение ссылки от владельца считается подтверждением почты для закрытого пилота. Аккаунт отмечается подтверждённым только после совпадения почты и одноразового токена.
- Пока нет SMTP и согласованного отправителя, восстановление пароля честно выполняется через владельца. Серверная команда создаёт одноразовую ссылку; публичная страница предлагает обратиться по указанному контакту и не обещает несуществующее письмо.
- При регистрации отдельно фиксируется принятие условий тестирования и информации об обработке данных.
- Любой frontend-сервис в режиме `api` показывает только реальные данные, честную пустоту или ошибку. Фикстуры допустимы исключительно в явном демонстрационном режиме.
- Незавершённые публикации, интеграции, календарь, рабочие настройки и биллинг отсутствуют в пилотном меню. Прямая ссылка показывает один понятный экран недоступности без этапов, токенов, провайдеров и тестовых кнопок.
- Реализация отдельного раздела идей сохраняется для оценки, но возможность на сервере выключена. Пока не пройдена проверка повторяемости, «Идеи» отсутствуют в меню, обучении, публичных обещаниях, редакторе и быстрых действиях; прямая ссылка честно сообщает о недоступности и не показывает ложный остаток попыток.
- Обучение состоит из трёх правдивых шагов: создать проект и публикацию, сохранить заметку в блокноте и добавить примеры стиля. Оно не обещает действие, которое текущий пилот выполнить не может.
- С экранов тестировщика убираются ID запросов, диагностика очередей, подписи режимов данных, сырые ошибки сервисов, технические слова о хранении, повторяющиеся действия проекта и дублирующие счётчики. Диагностика и учёт остаются в логах и постоянных записях.
- В production публикации исполняются через PostgreSQL outbox и Celery. API сохраняет очередь и отвечает; worker периодически забирает задания. Синхронный режим остаётся только для локальных тестов.
- API и worker работают от непривилегированного пользователя `app`, web — от встроенного пользователя `node`.
- Production-readiness действительно проверяет базу, Redis и точный Alembic head и отвечает `503`, если зависимость недоступна или схема отстаёт.
- Существующие пользователи, кабинеты, материалы, версии, медиа, публикации, учёт, сессии и подключения сохраняются.

## Данные и миграция

- Откат схемы разрешён лишь при отсутствии приглашений; иначе останавливается, чтобы не потерять след доступа.

- Ссылка показывается владельцу один раз и не должна попадать в логи приложения, Git, снимки или чат.

## Приёмка

- Закрытая регистрация без приглашения отклоняется.
- Приглашение действует только для своей почты, до истечения срока и один раз.
- Нужны оба согласия; приглашённый пользователь получает подтверждённую почту.
- Страницы подтверждения и сброса действительно вызывают API и показывают понятный результат.
- Токены подтверждения и сброса остаются скрыты в персональной ссылке и форме; без ссылки показывается понятная просьба обратиться к владельцу, а не техническое поле кода.
- Серверная команда создаёт рабочую одноразовую ссылку сброса; смена пароля завершает старые сессии.
- В API-режиме нет подмешивания фикстур в dashboard, материалы, проекты, стиль/примеры, публикации, интеграции, биллинг, кабинет, медиа и календарь.
- Прямые закрытые маршруты не показывают технические этапы, API, провайдеров, токены или mock-кнопки.
- Worker-режим возвращает очередь; worker идемпотентно обрабатывает событие и восстанавливает зависшую блокировку.
- Все прежние проверки 12K/12L/12M, блокнота, форм, лимитов, коннекторов, авторизации, публикаций и скрытой реализации идей остаются зелёными.
- Браузерная приёмка на телефоне и десктопе: регистрация по приглашению, вход, обучение, редактор, блокнот, аккаунт, закрытый маршрут, условия и данные.

- Просроченное приглашение заменяется новым; сырой токен не восстанавливается.

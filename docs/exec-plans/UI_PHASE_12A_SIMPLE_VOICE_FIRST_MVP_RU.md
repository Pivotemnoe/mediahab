# Задание для Codex - простой голосовой MVP Media Hub

Статус на 2026-07-29: Phase 12A реализована и локально проверена, включая проход с реальной авторизованной сессией API: запись голоса, загрузка в MinIO, расшифровка OpenAI, исправление и принятие текста, единая параллельная сборка всех пяти вариантов и копирование результата.

Во время живого прохода найдены и исправлены два интеграционных дефекта: повторный префикс `/api/v1` в серверных загрузчиках и гонка инициализации каталога площадок PostgreSQL при параллельной сборке вариантов.

## Главная цель

Переделать обычный пользовательский интерфейс Media Hub в простой голосовой помощник:

`выбрал рубрику -> надиктовал материал -> проверил текст -> отметил соцсети -> нажал Собрать -> получил готовые версии`

Пользователь не должен разбираться в проектах как в технических сущностях, этапах ИИ, блокировках фактов, очередях, коннекторах и публикационных заданиях.

## Что обязательно сохранить

- PWA и мобильный сценарий.
- Диктовку как главный способ ввода.
- Возможность надиктовать всё одним фрагментом или добавить несколько фрагментов по очереди.
- Общую редактируемую расшифровку перед сборкой.
- Проекты и рубрики.
- Отдельные правила каждой рубрики.
- 3-5 одобренных примеров постов для каждой рубрики.
- Общие примеры проекта только как запасной вариант, если у рубрики не хватает своих.
- Выбор нескольких соцсетей галочками.
- Отдельный результат для каждой выбранной соцсети.
- Ручную проверку человеком.
- Существующий backend, API и данные.

## Как должен работать пользовательский сценарий

### Экран 1. Создать

На первом экране сразу видны:

1. Проект.
2. Рубрика.
3. Галочки Telegram, MAX, VK, Instagram, Reels и действие `Выбрать все`.
4. Большая кнопка микрофона.
5. Кнопки `Пауза`, `Продолжить`, `Закончить фрагмент`, `Добавить ещё диктовку`.
6. Список записанных фрагментов по порядку.
7. Общая расшифровка, которую можно исправить.
8. Второстепенные действия `Вставить текст` и `Загрузить аудио или медиа`.
9. Одна главная кнопка `Собрать версии`.

Пользователь может надиктовать весь материал сразу или частями. Каждый новый фрагмент добавляется в конец. Перед сборкой пользователь видит и исправляет общий текст.

### Экран 2. Готовые версии

После одного нажатия `Собрать версии` система готовит все отмеченные соцсети.

Результаты появляются по мере готовности в отдельных вкладках:

- Telegram;
- MAX;
- VK;
- Instagram;
- Reels.

В каждой вкладке есть:

- готовый текст;
- количество знаков;
- желаемая длина;
- технический максимум;
- `Копировать`;
- `Редактировать`;
- `Короче`;
- `Живее`;
- `Без эмодзи`;
- `Пересобрать`;
- короткое поле для дополнительной команды.

Команда по умолчанию меняет только открытую вкладку. Для изменения всех версий должна быть отдельная явная галочка.

Если одна сеть завершилась ошибкой, готовые версии остальных сетей не пропадают.

### Экран 3. Настройки и рубрики

Обычная навигация содержит только:

- `Создать`;
- `История`;
- `Настройки`.

В настройках проекта есть раздел `Рубрики`.

Для каждой рубрики пользователь задаёт простыми русскими полями:

- название и цель;
- какие факты нужны;
- структуру поста;
- желаемую длину;
- тон;
- обязательные и запрещённые элементы;
- 3-5 хороших примеров постов;
- используемые соцсети.

У площадки отдельно задаются:

- желаемое количество знаков;
- технический максимум;
- формат;
- эмодзи;
- хэштеги;
- CTA;
- запрещённые слова и конструкции.

При необходимости рубрика может переопределить правило одной площадки, но эта возможность не должна усложнять обычный экран.

## Как собирать несколько соцсетей

Пользователь не проходит Telegram, MAX, VK, Instagram и Reels вручную по очереди.

Он отмечает нужные площадки и запускает сборку один раз.

Внутренняя логика:

1. Из принятой расшифровки создаётся один мастер-текст по правилам выбранной рубрики.
2. Система рассчитывает действующие правила каждой выбранной площадки.
3. Если Telegram, MAX и VK имеют одинаковые правила и текст укладывается во все лимиты, можно использовать один вариант и показать его в трёх отдельных вкладках.
4. Если правила отличаются, версии собираются отдельно.
5. Instagram всегда получает отдельную адаптацию.
6. Reels получает отдельный сценарий и подпись.
7. Независимые версии можно готовить параллельно; интерфейс показывает их по мере готовности.

VK и Reels на этом этапе работают как ручное копирование/экспорт. Автопубликация для новой сети требует отдельного backend-коннектора и в эту задачу не входит.

## Первый этап, который нужно реализовать сейчас

Работать только над Phase 12A. Не пытаться одновременно переделать весь SaaS.

1. Прочитать `AGENTS.md`, `README.md`, `docs/en/MASTER_SPEC.md` и английский план `UI_PHASE_12A_SIMPLE_VOICE_FIRST_MVP.md`.
2. Проверить и сохранить уже существующие незакоммиченные изменения. Не перезаписывать чужую работу.
3. Заменить обычный вход `/app` простым голосовым экраном.
4. Загружать существующие проекты и рубрики через текущие сервисы.
5. Дать выбрать одну рубрику и несколько соцсетей.
6. Подключить существующую запись/загрузку аудио, расшифровку и принятие текста.
7. Поддержать несколько голосовых фрагментов и их объединение по порядку.
8. Подключить существующую сборку мастер-текста и вариантов площадок.
9. Показать варианты выбранных сетей в отдельных вкладках.
10. Оставить текущую сложную студию только под кнопкой `Расширенный режим`.
11. Сократить обычную навигацию до `Создать`, `История`, `Настройки`.
12. Не менять API и базу данных без доказанной необходимости.

Редактор рубрик и примеров не делать в Phase 12A. На этом этапе нужно правильно использовать уже сохранённые правила и примеры. Простой редактор рубрик будет отдельной Phase 12B после проверки главного голосового сценария.

## Чего нельзя делать

- Не удалять существующие backend-модули и данные.
- Не добавлять новые технические панели в обычный сценарий.
- Не показывать UUID, outbox, очереди, retry, JSON Schema, сырые промпты и названия внутренних фаз.
- Не превращать диктовку снова в один из пяти второстепенных блоков.
- Не заставлять пользователя запускать отдельную сборку для каждой соцсети.
- Не обещать автоматическую публикацию в VK и Reels без backend-коннекторов.
- Не хардкодить проект `Что поесть? Армавир` в логике приложения.
- Не трогать существующие данные, публикации и Docker volumes.

## Проверка готовности

На мобильной ширине 390 px пользователь должен:

1. Открыть приложение.
2. Выбрать проект и рубрику.
3. Отметить несколько соцсетей.
4. Записать три голосовых фрагмента.
5. Исправить одну фразу в общей расшифровке.
6. Один раз нажать `Собрать версии`.
7. Получить отдельные вкладки всех выбранных площадок.
8. Скопировать готовый вариант без перехода в расширенный режим.

Первое действие с микрофоном должно быть доступно максимум за два нажатия после открытия PWA.

Перед завершением выполнить проверки из английского плана, визуально проверить 390, 768, 1440 и 1920 px и написать короткий русский отчёт: что изменено, что проверено, какие ограничения остались и какой следующий маленький этап рекомендуется.

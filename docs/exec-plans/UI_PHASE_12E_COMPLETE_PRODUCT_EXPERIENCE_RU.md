# UI Phase 12E — цельный путь от посадочной до готовых постов

## Статус

Реализовано локально 02.08.2026. Production, backend, база данных и публикации не изменялись.

## Цель

Провести человека по понятному маршруту:

`понял пользу -> зарегистрировался или вошёл -> надиктовал или вставил идею -> выбрал площадки и длину -> проверил отдельные версии -> вернулся к черновикам или голосовым заметкам`.

Главное действие — голос. Блокнот остаётся полноценным разделом для голосовых и текстовых заметок.

## Объём

- Доделать полноценную посадочную страницу: обещание продукта, живой пример, три шага, правила Telegram/MAX/VK/Instagram, сценарии для разных авторов, контроль результата, FAQ, финальный призыв и подвал.
- Привести страницы возможностей, тарифов, безопасности, контактов и юридические оболочки к той же визуальной системе и человеческому языку.
- Связать вход и регистрацию с обещанием посадочной и убрать из видимых текстов формулировки для программиста.
- Вместо перегруженной верхней навигации сделать тонкое постоянное меню слева:
  - «Создать»;
  - «Черновики»;
  - «Блокнот»;
  - «Мой стиль»;
  - раскрываемое «Ещё» для проектов, публикаций, календаря, медиа, интеграций, рабочего пространства, аккаунта, тарифа и настроек.
- Добавить понятную верхнеуровневую страницу «Мой стиль», которая ведёт к уже существующим правилам проекта, рубрикам и примерам без терминов про промпты и схемы.
- На телефоне сохранить компактное нижнее меню; все существующие страницы кабинета должны получить общую новую оболочку.
- Переписать главный экран, блокнот и вход в настройки вокруг задач автора, а не технических этапов разработки.
- Не менять существующую логику диктовки, блокнота, проектов, ИИ, вариантов, публикаций, авторизации и API.

## Вне объёма

- Backend, схема базы, миграции, OpenAPI, провайдеры, коннекторы, автоматизация отправки, реальные платежи, деплой и production-данные.
- Удаление расширенных возможностей: они остаются доступными через постепенное раскрытие меню.
- Обещания живой публикации или оплаты там, где текущая реализация требует ручной либо внешней настройки.
- Удаление ручного подтверждения перед публикацией.

## Риски

- Боковое меню может сузить мастер. Поэтому оно будет тонким и исчезнет ниже компьютерной ширины.
- На старых страницах есть технические тексты. Сначала исправляются общие оболочки и самые частые точки входа, а честные ограничения сохраняются на детальных страницах.
- В рабочей копии уже есть незакоммиченные изменения UI Phase 12D. Новая работа строится поверх них, ничего постороннего не откатывается.
- Для визуальной проверки может понадобиться fixture-режим, потому что API-режим закрыт авторизацией. Авторизация ослабляться не будет.

# UI Phase 12L — Пересборка из исходника, сила стиля и доверие к ссылкам

## Статус

Реализовано и локально проверено 13.08.2026. Production deployment и обновление rich footer проекта владельца ещё не выполнены.

## Цель

Позволить исправить слабую готовую версию, не уходя из «Наговори»:

`авторский исходник -> новый мастер из исходника -> усиленный стилевой контекст -> новые версии площадок -> сохранение всех предыдущих редакций`.

Сервис также должен отличать обычный текст подвала от подвала, в котором действительно есть ссылки.

## Подтверждённый диагноз

- Production-кнопка `Пересобрать` вызывала доработку платформенной версии и поэтому редактировала уже слабый текст, а не возвращалась к диктовке автора.
- Команда `Больше юмора` добавила три локальные фразы, но сохранила прежние заголовок, композицию разделов, итог и вёрстку оценок.
- В production-проекте 13 одобренных примеров, но только два напрямую относятся к `Фаст-обзору`; мастер получал четыре примера, доработка — три.
- Правила юмора проекта доходили до провайдера только внутри большого обрезанного JSON и не были сформулированы как отдельная редакционная цель.
- В production-подвале есть видимые слова Telegram, MAX, сайт и другие обзоры, но отсутствует `footer_rich_text`; интерфейс при этом ошибочно говорил, что подвал со ссылками включён.
- Последняя ручная Telegram-редакция автора уже хранится как неизменяемая revision и не должна быть перезаписана этим этапом.

## Продуктовые решения

- Переименовать действие результата в `Пересобрать из диктовки` и запускать полный конвейер мастера из исходника. Текущая платформенная версия не является основным источником этого действия.
- Пересобирать все выбранные площадки, потому что они используют новый общий master revision. Предыдущие мастера и версии площадок остаются в истории.
- Подбирать до шести одобренных примеров для мастера и до пяти для доработки площадки. Сначала предпочитать рубрику, но использовать сильные общие примеры проекта, пока библиотека рубрики мала.
- Передавать правила юмора отдельным явным слоем prompt. Если настройки задают плотность или количество шуток, модель выполняет это требование только на основе наблюдений из авторского исходника.
- Примеры остаются недоверенными образцами `style_only`. Они могут учить композиции, ритму и интенсивности юмора, но не дают факты, тему, вывод или узнаваемые фразы.
- Полностью убрать контроль плотности абзацев и автоматическое склеивание абзацев из гигиены текста. Оставить только безопасную нормализацию пробелов и защиту от неестественных конструкций с тире. Сервис не переставляет абзацы за автора.
- Называть подвал ссылочным только тогда, когда в rich-text есть хотя бы одна валидная HTTP(S)-ссылка. Иначе показывать предупреждение, что подвал обычный, и вести владельца к правилам проекта.
- Сообщение копирования говорит `зашитые ссылки скопированы` только при реальном наличии ссылок в скопированном rich-text.
- Обучение на финальной ручной редакции остаётся явным решением автора через `Запомнить эту редакцию`; обычное сохранение промежуточной правки не обучает проект скрытно.

## Объём backend

- Увеличить ограниченную выборку примеров для `assemble_master` и `refine_variant` без изменения схемы базы.
- Добавить отдельные ограниченные инструкции юмора в master/refinement prompts и закрепить контракт тестами.
- Удалить обнаружение/склеивание дробных абзацев и связанный текст повторной попытки, сохранив нормализацию пробелов и проверку тире.
- Не менять границу авторского источника, locked facts, неизменяемые revisions, учёт использования и сохранение последнего хорошего результата.

## Объём frontend

- Направить `Пересобрать из диктовки` в существующий восстанавливаемый полный конвейер, а не в `/platform-variants/{id}/refine`.
- Объяснить, что будет создан новый мастер и новые версии выбранных площадок, а прежние редакции сохранятся.
- Добавить `footerLinkCount` в серверную view model и честно показывать ссылочный/обычный подвал.
- Формировать сообщение копирования по фактическим link marks выбранной версии.
- Оставить явное действие `Запомнить эту редакцию` заметным после ручной правки.

## Preset и production-конфигурация

- После деплоя обновить rich footer только у действующего production-проекта. Не добавлять адреса конкретного проекта в переиспользуемый preset или код приложения.
- После проверки кода обновить активный production-проект через versioned project API подтверждёнными URL Telegram, MAX и сайта. `Другие обзоры` временно ведут на публичный раздел/корень сайта, пока нет отдельного URL архива.
- Исторические варианты не меняются; новые версии получают текущий rich footer.

## Приёмка

- Нажатие `Пересобрать из диктовки` создаёт новый master revision с предыдущим мастером как parent и новые версии всех выбранных площадок.
- Запрос провайдера содержит авторский исходник и одобренные стилевые примеры, но не считает текущую ручную платформенную редакцию достоверным исходником.
- При наличии предпочитается хотя бы один пример той же рубрики; ограниченный fallback может использовать библиотеку проекта.
- Явные правила юмора присутствуют в system prompt мастера и доработки, а примеры помечены `untrusted_style_only`.
- Ни prompt, ни validator, ни normalizer не содержит правил дробления абзацев и не склеивает короткие абзацы.
- Обычный подвал показывает `подвал добавлен, ссылки не настроены`; rich footer показывает точное число ссылок.
- Успешное копирование не заявляет о ссылках, если link marks равны нулю.
- Текущая production-редакция автора остаётся byte-for-byte неизменной после deploy и обновления конфигурации.
- PostgreSQL, Redis, их volumes и Caddy не пересоздаются при выкладке.

## Проверка

- Проходят backend regression tests для prompt/retrieval, неизменяемой истории и отказа от блокирующей абзацной гигиены.
- Frontend-контракт проверяет маршрут полной пересборки, рабочую ссылку в настройки проекта и честный статус подвала.
- Локальные результаты: backend `165/165`; editorial surface `14/14`; AI examples pipeline `14/14`; TypeScript и Web lint проходят; UI hardening проходит; production Web build собирает `35/35` страниц; compileall и `git diff --check` проходят.
- Перегенерировать OpenAPI только при изменении API DTO; этот этап спроектирован без такого изменения.
- После локальных тестов выполнить одну живую пересборку в workspace владельца, сохранить существующую ручную версию и сверить точные факты результата с исходником.

## Риски и откат

- Большее число примеров увеличивает prompt и стоимость. Ограничения остаются шесть/пять, маршрутизация модели не меняется.
- Юмор семантичен; детерминированный подсчёт шуток даст ложные срабатывания. Этап усиливает явный prompt-контракт и проверяется реальным примером владельца вместо хрупкой блокировки по словам.
- Полная пересборка дороже локальной правки. Название и подсказка явно показывают эту границу.
- Откат возвращает предыдущие stateless images и предыдущую активную версию проекта. Downgrade схемы и перезапуск stateful-сервисов не нужны.

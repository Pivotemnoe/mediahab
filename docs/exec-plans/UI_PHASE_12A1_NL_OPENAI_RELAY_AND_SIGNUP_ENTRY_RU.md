# UI Phase 12A.1 - NL-прокси OpenAI и вход через регистрацию

## Статус

Реализовано, локально проверено и выложено в production 2026-07-29. Это небольшой эксплуатационный этап после проверенного голосового MVP Phase 12A. Он не заменяет запланированный редактор рубрик Phase 12B.

Подтверждено:

- NL-прокси получил реальный ответ OpenAI со списком моделей.
- Прямой CONNECT из локальной российской сети зависал, поэтому для текущего теста поднят защищённый локальный SSH-forward до того же NL-прокси, как в уже применяемой туннельной схеме.
- Реальный запрос Media Hub Responses через SSH и NL успешно выполнен моделью `gpt-4.1-mini`.
- Регистрация в локальном PostgreSQL и последующий запрос `/me` с cookie-сессией вернули HTTP 200.
- Гость получает 307 с `/app` на `/login?next=/app`, а авторизованный встроенный браузер открыл голосовой экран.
- Первая страница и форма регистрации проверены во встроенном браузере; все четыре поля обязательны.
- Прошли lint, typecheck, production build, 5 общих тестов, 51 тест API и `git diff --check`.
- Production-релиз `20260729-094025` работает на `https://temichev-posthub.ru`, RU-хост `89.169.46.92`.
- Публичные главная, регистрация, вход, liveness и readiness вернули HTTP 200; гость получил 307 с `/app` на `/login?next=/app`.
- Технический production-smoke аккаунт прошёл регистрацию, `/me`, авторизованный `/app` и выход с HTTP 200. После проверки сессия отозвана.
- Реальный структурированный запрос из production API-контейнера прошёл через авторизованный NL-прокси `5.129.239.104:18080` и получил ответ `gpt-4.1-mini`.
- Container ID PostgreSQL и Redis не изменились при переключении. Caddy остался активен, соседний сайт сохранил ожидаемый ответ HTTP 401.

Важно для выкладки: ранее задокументированный обратный туннель Media Hub на RU-порту `22089` не работает и не использовался. Production RU-хост напрямую достигает авторизованного NL-прокси с allowlist, поэтому используется отдельная серверная настройка `OPENAI_PROXY_URL`. На трафик S3 и социальных коннекторов эта настройка не распространяется.

## Цель

Сделать текущий MVP доступным для проверки с российского телефона или ноутбука без VPN на самом устройстве:

1. Все серверные запросы Media Hub к OpenAI направлять через отдельный защищённый NL-прокси на `5.129.239.104`.
2. На публичной первой странице явно вести нового пользователя к рабочей регистрации, а существующего - ко входу.
3. Не пускать браузер без действующей сессии в обычный интерфейс `/app`.

Ключ OpenAI и учётные данные прокси остаются только на серверной стороне и не попадают в браузер, исходный код, логи, скриншоты или коммит.

## Предварительная проверка

- На NL-сервере уже работает `mediahub-openai-proxy.service`.
- Это авторизованный HTTP CONNECT-прокси с разрешением только на `api.openai.com:443`; он не является общедоступным универсальным прокси.
- Media Hub вызывает OpenAI только из FastAPI через `httpx`: Responses, embeddings и расшифровка аудио.
- Backend уже умеет регистрировать пользователя, хешировать пароль Argon2id, создавать workspace и бесплатную подписку, а также выдавать защищённую cookie-сессию.
- Отправка письма подтверждения не входит в этот личный тест. Реальная почта сохранится как адрес аккаунта, но подтверждение владения адресом пока не обещается.

## Реализация

- Добавить необязательную серверную настройку `OPENAI_PROXY_URL`.
- Через один общий конструктор OpenAI-клиента подключить прокси к текстовой генерации, embeddings и расшифровке.
- Не применять общий `HTTPS_PROXY`, чтобы случайно не отправить через NL запросы S3 и социальных коннекторов.
- Не добавлять учётные данные в репозиторий; документировать только имя настройки.
- Сделать регистрацию главным публичным действием, оставить заметную кнопку входа и обязательные поля формы.
- В API-режиме проверять сессию на сервере перед показом `/app`; без неё направлять на `/login`.
- В режиме демо-фикстур сохранить возможность смотреть дизайн без backend.

## Данные и миграции

Миграция не нужна. Пользователи, рабочие пространства, сессии, материалы, медиа, публикации, Docker volumes и пресеты не изменяются и не удаляются.

Предварительная production-проверка подтвердила Alembic `202606200008 (head)`, поэтому миграция не запускалась. До переключения создан и проверен PostgreSQL dump в custom-формате вместе с защищённой копией конфигурации: `/var/backups/media-hub/20260729-094025`. Production-smoke добавил один явно помеченный технический аккаунт и workspace с адресом `example.test`; реальной почты и редакционных данных в нём нет.

## Риски и откат

- Адрес прокси содержит секретные учётные данные и хранится только в защищённом окружении.
- Пока окончательный RU-хост не закреплён, прокси защищён авторизацией и списком разрешённых назначений; позже желательно также ограничить вход по IP.
- Реальная почта пока не подтверждается письмом.
- Для отката достаточно убрать `OPENAI_PROXY_URL` и вернуть прежнее поведение публичного входа. Данные и хранилище откатывать не требуется.
- Для быстрого отката сохранены образы `media-hub-{api,worker,web}:rollback-20260729-094025`; пересоздавать нужно только эти три stateless-сервиса.
- Дамп `/var/backups/media-hub/20260729-094025/media_hub.dump` восстанавливается только после отдельного подтверждения восстановления базы. Обычный откат приложения не пересоздаёт PostgreSQL, Redis и их volumes.

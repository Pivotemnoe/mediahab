# UI Phase 12A.4 - Возврат из истории и постоянные блоки со ссылками

## Статус

Реализовано, опубликовано и проверено на production 2026-07-31.

## Цель

Дать пользователю возможность открыть сохранённый материал из «Истории», исправить исходный текст и собрать новые ревизии площадок без повторной диктовки. Дать каждому проекту постоянный подвал, включая обычные URL, который без изменений сохраняется в готовом, доработанном, скопированном и опубликованном тексте.

### Локальное продолжение: доработка сохранённой версии

Добавить в каждую готовую карточку площадки компактное действие `Доработать`. Оно использует существующий простой редактор, сразу открывает выбранную сохранённую версию и показывает уже реализованные команды ручной правки, сокращения, оживления, юмора, удаления эмодзи, пересборки и свободной команды без обязательной полной пересборки всех площадок. Сохраняются тот же `ContentItem`, старые ревизии, медиа, проект, рубрика, выбор площадок и постоянный подвал. До отдельного разрешения владельца production не изменяется.

## Продуктовые решения

1. На странице материала рядом с исходным текстом появляется действие `Поправить исходник и пересобрать`.
2. Действие продолжает тот же `ContentItem`: дубль не создаётся, старые ревизии не удаляются.
3. Проект и рубрика восстанавливаются и фиксируются на время продолжения. Уже прикреплённые фотографии остаются у материала.
4. По возможности восстанавливается прежний набор площадок; иначе остаются Telegram и MAX.
5. Изменённый исходник создаёт ревизию материала и снимает старую фиксацию факта до новой мастер-сборки.
6. В общих правилах проекта появляется одно необязательное поле постоянного подвала. Обычные ссылки `https://` хранятся как текст и сохраняются при копировании. Постоянной шапки нет.
7. Постоянные блоки добавляются кодом приложения после ИИ и входят в лимит площадки. ИИ не должен воспроизводить или переписывать их.
8. Доработка ИИ применяется к телу поста, после чего точный текущий подвал проекта возвращается.
9. Миграция данных не нужна: поля хранятся в уже версионируемом JSON `cta_config`.
10. У каждой готовой версии площадки на странице сохранённого материала есть своё действие `Копировать`. В буфер попадает текст вместе с точным постоянным подвалом.
11. У каждой готовой версии есть и действие `Доработать`. Оно передаёт ключ площадки в режим продолжения и загружает последнюю сохранённую версию без создания дубля и без обязательной полной пересборки.

## Реализация

- Добавить модель продолжения существующего материала с исходным блоком, числом медиа и последними площадками.
- Добавить обработку `edit=<content_id>` в `/app/content/new`.
- Заполнять простой редактор существующим материалом, расшифровкой, полем/блоком исходника, рубрикой, площадками и числом фото.
- Добавить кнопку на странице истории и понятное сообщение о режиме продолжения.
- Добавить копирование у каждой готовой версии площадки на странице сохранённого материала.
- Добавить `footer_template` в правила проекта, не стирая остальные настройки CTA.
- Добавить общие функции постоянных блоков для генерации площадок и ИИ-доработки.
- Сохранить ручную правку варианта и не допускать повторного добавления постоянных блоков.
- Загружать последние сохранённые версии в режиме продолжения и активировать выбранную на странице материала площадку.
- Добавить безопасное для мобильного экрана действие `Доработать` рядом с `Копировать`; использовать существующие API и редактор, а не создавать новый.

## Проверки

- Тест view model на продолжение того же материала.
- Компонентная и браузерная проверка кнопки из истории и заполненного редактора.
- Unit-тесты точного добавления подвала, отсутствия дублей и удаления блока перед ИИ-доработкой.
- Тесты публикации, подтверждающие, что постоянные ссылки входят в лимиты MAX и Instagram.
- `make lint`, `make typecheck`, сфокусированные и полные тесты, production-сборка web и релевантный браузерный smoke.
- Приёмка продолжения на 390 px и 1440 px: в каждой готовой карточке есть `Доработать`, выбранная сохранённая версия сразу открывается с командами доработки, горизонтального переполнения нет, новый `ContentItem` до и после доработки не создаётся.

## Результат проверки

- Локальное продолжение с прямой доработкой прошло приёмку на 390 px и 1440 px на изолированном API-материале: в каждой готовой карточке есть `Копировать` и `Доработать`, выбранная сохранённая версия MAX/Telegram сразу открывается в существующем редакторе, все шесть быстрых команд доступны, постоянный подвал присутствует ровно один раз, горизонтального переполнения нет. Загрузка и открытие редактора не создают новый материал. Production не изменялся.

- Сфокусированные тесты подвала и ревизий публикации проходят: проверены обычные ссылки Telegram/MAX, отсутствие дублей, ручная правка, игнорирование старого значения шапки и лимиты площадок.
- `make lint`, `make typecheck`, `make test` и `make test-e2e` проходят.
- Production-сборка Next.js завершается успешно.
- Авторизованная локальная проверка на реальном API выполнена при ширине 390 px и 1440 px: в истории был один реальный материал без fixtures, на странице материала были кнопка продолжения и отдельное копирование каждой готовой версии, горизонтального переполнения не было.
- Кнопка продолжения открыла существующий простой голосовой редактор по адресу `/app/content/new?edit=<content_id>`. Проект и рубрика остались заблокированы, Telegram и MAX восстановились, число прикреплённых фотографий осталось равным одному.
- Реальная локальная пересборка оставила ровно один `ContentItem`, сохранила фотографию и две прежние версии площадок, добавила две новые версии и оставила постоянный подвал ровно один раз в каждом новом тексте и результате копирования.
- Контракт OpenAPI и схема базы не менялись; миграция и регенерация клиента не требуются.

## Риски и откат

- Длинный постоянный подвал может превысить лимит площадки; существующая валидация должна показать ошибку, а не обрезать ссылку.
- Старые версии проекта остаются неизменяемыми. Текущий активный подвал считается актуальным оформлением канала и применяется при пересборке старого материала; сохранённый исходник и прежние версии при этом не изменяются.
- Для отката достаточно убрать кнопку продолжения и детерминированное добавление блоков. Сохранённые JSON-поля могут безопасно остаться в исторических версиях; откат базы не нужен.

# Phase 12B.2: форматы Instagram

Статус: реализовано и проверено локально
Дата: 1 августа 2026
Область: существующий Voice First композер и payload версии площадки; без нового верхнеуровневого экрана, автопубликации, деплоя и изменения production

## Цель

При выборе Instagram пользователь обязан указать один формат:

- `image` — один готовый визуал (фото или видео) и одна подпись;
- `carousel` — 2-10 готовых фото/видео с сохранением порядка, первый элемент является обложкой;
- `reel` — одно готовое видео плюс metadata подписи, сценарного плана и подсказки обложки.

Формат сохраняется как snapshot текущей сборки и не меняет правила проекта или рубрики.

## Данные и API

- Добавить в `GenerateVariantsRequest` необязательный `instagram_format: image | carousel | reel`.
- Старые прямые вызовы API без поля сохраняют совместимость Phase 09; новый простой композер всегда передаёт формат и не разрешает сборку Instagram без выбора.
- Если новое поле передано, backend проверяет количество и тип медиа.
- В `PlatformVariant.payload` сохраняются `instagram_format`, упорядоченное краткое описание медиа и id обложки.
- Миграция БД не нужна: payload уже JSON, порядок уже хранится в `ContentMedia`.

## Интерфейс

- Показывать карточки формата только при выбранном Instagram.
- Начальное значение пустое, чтобы намерение публикации было явным.
- Обычным русским языком объяснять нужное количество медиа.
- Блокировать `Собрать версии` и показывать конкретную подсказку, пока формат и прикреплённые медиа несовместимы.
- Показывать выбранный формат в результате Instagram.

## Проверки

- Unit/integration-тесты image, carousel, reel, отсутствующего медиа, неверного типа и snapshot payload.
- Typecheck/build фронтенда.
- Responsive smoke 390 px и 1440 px.

## Результат

- Существующий композер теперь требует `image`, `carousel` или `reel` только при выбранном Instagram и блокирует сборку с конкретной русской подсказкой, пока медиа не подходят формату.
- Фото и MP4/MOV загружаются через существующий медиаконтур. Формат, snapshot порядка медиа и id обложки сохраняются при ручном редактировании и ИИ-доработке ревизий.
- Instagram получает одну форматную доработку: подпись для одиночного поста, подпись и последовательный план карточек для карусели либо хук, сценарий, подпись и подсказку обложки для Reel. Постоянный подвал по-прежнему добавляет приложение.
- Старые API-клиенты без `instagram_format` продолжают работать по правилам Phase 09.

Проверено 1 августа 2026 года:

- `make typecheck` — успешно;
- `make lint` — успешно;
- `make openapi` — успешно, оба хранимых OpenAPI-файла обновлены;
- `make test` — успешно, включая 76 API-тестов и 5 общих тестов репозитория;
- `pnpm --filter @temichev/web build` — успешно, сгенерированы 32 статические страницы;
- локальная проверка во встроенном браузере — 390 px и 1440 px, горизонтального переполнения нет, выбор формата виден, несовместимый Reel блокирует сборку.

Миграция БД не понадобилась. Production не изменялся.

## Риски и откат

- Старые тесты и коннектор Phase 09 используют legacy-запросы; совместимость сохраняется, а обычный PWA переходит на строгий сценарий.
- Readiness обработки медиа остаётся в существующем контуре; участвуют только прикреплённые неудалённые assets.
- Для отката удалить поле запроса, metadata/валидацию payload и UI-блок. Откат данных не нужен.

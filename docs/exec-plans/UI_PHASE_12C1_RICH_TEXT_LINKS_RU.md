# UI Phase 12C.1 — безопасный редактор ссылок в тексте

## Статус

Реализовано и принято локально 2026-08-01. Production требует отдельного подтверждения владельца.

## Цель

Дать пользователю возможность выделить любое слово или фразу в готовой версии площадки либо постоянном подвале, зашить в выделение безопасную ссылку и скопировать результат с кликабельными ссылками для Telegram-совместимой вставки. Сохраняются простой голосовой сценарий, неизменяемые ревизии, детерминированный подвал, лимиты площадок и ручное подтверждение публикации.

## Продуктовые решения и допущения

1. Расшифровка остаётся обычным текстом. Форматирование доступно только в готовых версиях и постоянном подвале.
2. В базе хранится ограниченный JSON-документ, а не произвольный HTML. Версия 1 разрешает обычный текст и отметки `link`, `bold`, `italic`.
3. Ссылки должны начинаться с `https://` или `http://`; опасные схемы отклоняют и интерфейс, и API.
4. `PlatformVariant.text` и `rendered_text` остаются каноническим обычным текстом для подсчёта длины и интеграций без форматирования.
5. Форматирование версии хранится в `payload_json` этой неизменяемой ревизии. Ручное редактирование создаёт новую ревизию и не меняет старую.
6. Постоянный подвал сохраняет `footer_template` как совместимый обычный текст, а структурную версию — в версионируемом `cta_config.footer_rich_text`.
7. Полная ИИ-пересборка не переносит ссылки на переписанные слова. Новый основной текст начинается без форматирования, а актуальный подвал снова добавляется вместе со своими ссылками.
8. Копирование записывает `text/html` и `text/plain`; если браузер не поддерживает rich clipboard, используется обычный текст.
9. Telegram и MAX смогут получить разметку из того же безопасного документа. Остальные направления используют обычный текст, пока их коннектор явно не поддержит форматирование.
10. Первая панель ограничена ссылкой/удалением ссылки, жирным, курсивом, отменой и повтором.

## Данные и API

- Миграция таблиц не нужна: используются существующие версионируемые JSON-поля.
- В API появляется общая схема, проверка и нормализация rich text.
- Запрос ручного редактирования версии получает необязательный rich-text документ. Обычный текст вычисляет и проверяет сервер.
- Rich text возвращается внутри существующего `payload` для обратной совместимости.
- `footer_rich_text` проверяется при создании, изменении и импорте проекта; обычный fallback синхронизируется.
- При изменении контракта обновляются OpenAPI и типизированный frontend-клиент.

## Интерфейс

- Один переиспользуемый безопасный редактор для подвала проекта и готовых версий.
- Выделение текста, добавление/изменение/удаление ссылки, жирный, курсив, undo и redo.
- Сохранённые ссылки заметны и доступны с клавиатуры в режиме просмотра.
- Все нужные кнопки копирования получают rich clipboard без потери обычного fallback.
- На 390 px нет горизонтального скролла и элементы удобны для касания; на 1440 px редактор остаётся читаемым.

## Тесты и приёмка

- Unit-тесты нормализации, запрета опасных URL, вычисления обычного текста, экранирования HTML, подвала и старого fallback.
- API-тесты: rich-редактирование создаёт новую ревизию, старую сохраняет, подвал не дублирует, изоляция workspace соблюдается.
- Интерфейсная приёмка: выделение слов, установка/удаление ссылки, сохранение, повторное открытие, rich/plain clipboard.
- Реальная API-backed история без fixtures на 390 px и 1440 px; новый `ContentItem` не создаётся.
- `make lint`, `make typecheck`, фокусные и полные тесты, `make test-e2e`, обновление/проверка OpenAPI и production-сборка web.

## Риски и откат

- Поддержка HTML-буфера различается между браузерами. Сохраняются честное состояние ошибки/успеха и `writeText` fallback.
- Структурный и обычный текст могут разойтись, если принимать их независимо. API всегда нормализует документ и сам вычисляет канонический текст.
- Возможности разметки площадок отличаются. Коннекторный рендерер не должен пропускать неподдерживаемые теги или небезопасные URL.
- При откате новые JSON-поля можно игнорировать и вернуть обычные редакторы. Старые `footer_template`, тексты, ревизии, публикации, медиа и схема базы останутся рабочими.

## Результат проверки

- Прошли фокусные тесты rich text, подвала, ревизий, запрета опасных ссылок и рендеринга Telegram/MAX.
- Прошли `make lint`, `make typecheck`, `make test` и экспорт OpenAPI. Полный API-набор: 90 тестов.
- Реальный локальный API-backed сценарий создал один проект и один `ContentItem`, сохранил подвал со ссылкой, собрал Telegram/MAX и повторно открыл подвал с той же ссылкой.
- Telegram-версия показала подвал настоящей ссылкой. Проверка буфера подтвердила один элемент одновременно с `text/html` (включая `<a>`) и `text/plain` fallback.
- В редакторе готовой версии доступны ссылка/удаление ссылки, жирный, курсив, undo и redo. На 390 и 1440 px видны все шесть команд, а `scrollWidth` равен `clientWidth`.
- Параллельная локальная сборка Telegram/MAX также выявила и исправила прежнюю гонку SQLite-каталога: теперь там применяется такой же идемпотентный upsert, как в PostgreSQL.
- Миграция таблиц не нужна; старые обычные тексты и подвалы совместимы.

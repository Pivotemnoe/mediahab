# UI Phase 12B.4 — Проверка результата перед экспортом

Статус: реализовано и проверено локально 1 августа 2026 года. Production не изменялся.

## Цель

Добавить в каждый существующий результат площадки компактную проверку перед экспортом: длина, медиа, формат и готовность способа отправки. Новый экран и новая архитектура публикации не создаются.

## Допущения и границы

- Проект остаётся обязательным, рубрика — необязательной.
- Каждая площадка сохраняет собственный `PlatformVariant`; ошибка одной площадки не удаляет готовые результаты остальных.
- Preflight сохраняется снимком внутри `PlatformVariant.validation`, но не утверждает и не публикует версию.
- В простом редакторе не выбирается конкретный аккаунт или направление публикации. Поэтому нельзя сообщать, что живое подключение готово: проверка должна честно показать ручной экспорт или необходимость проверить подключение.
- Перед публикацией по-прежнему обязательно подтверждение человека.
- В этап не входят миграция БД, новый маршрут верхнего уровня, изменение секретов, включение коннектора и deploy production.

## Контракт API

`PlatformVariant.validation.preflight` содержит:

- `status`: `pass | warning | block`;
- `checks`: четыре упорядоченные проверки `length`, `media`, `format`, `delivery`;
- каждая проверка содержит стабильные `key`, `status`, `code`, русские `label` и `message`.

Снимок создаётся вместе с версией площадки и пересчитывается при явной повторной валидации. Существующие поля `valid`, `errors`, `warnings`, пределы и payload остаются совместимыми.

## Интерфейс

- Показывать блок проверки внутри активной карточки результата перед готовым текстом.
- У каждой проверки должны быть видимый текстовый статус и пояснение; цвет используется только дополнительно.
- Сделать блок подписанной областью статуса с мягким live-обновлением и возможностью фокуса с клавиатуры.
- Сохранить существующие независимые результаты и действия по каждой площадке.

## Тесты

- Модульно проверить блокирующий hard limit, формат/медиа Instagram и ручную готовность VK.
- Интеграционно проверить наличие снимка preflight в созданной и отредактированной версии.
- Запустить тесты API и репозитория, lint фронтенда, TypeScript, production build и адаптивную проверку 390 px и 1440 px.

## Риски и откат

- Риск: capability коннектора может быть ошибочно воспринят как проверенный аккаунт. Мера: до проверки конкретного направления показывать предупреждение; для ручных площадок прямо писать о ручном экспорте.
- Риск: старый клиент не передаёт формат Instagram. Мера: сохранить совместимость и показать необходимость проверить формат, а не отклонять старый запрос.
- Откат: удалить добавочный снимок `validation.preflight` и его блок в интерфейсе. Миграция схемы и данных не требуется.

## Результаты проверки

- Узкие модульные тесты preflight: 5 успешно.
- Узкие интеграционные тесты Instagram/VK: 8 успешно.
- Полный набор API: 81 тест; набор репозитория: 5 тестов — всё успешно.
- Успешны `make lint`, `make typecheck`, `make openapi` и production build Next.js.
- Локальная браузерная проверка 390 × 844 и 1440 × 900 не обнаружила горизонтального переполнения.
- Миграция БД не потребовалась. Production, секреты и живые направления не изменялись.

# UI Phase 12F — бренд «Наговори» и офлайн-блокнот

## Статус

Реализовано и локально проверено 7 августа 2026 года. Владелец подтвердил app-only deploy в production; выполняется выпуск.

## Цель

Выпустить пользовательский бренд **«Наговори»** со слоганом **«Твои мысли. Твой стиль. Твои публикации.»** и сделать блокнот устойчивым к отсутствию доступа к production-домену:

`открыть установленное PWA -> написать или записать заметку -> сохранить на телефоне -> дождаться связи -> синхронизировать и расшифровать -> получить ровно одну серверную заметку`.

Домен остаётся `temichev-posthub.ru`. Названия репозитория, пакетов, cookies, таблиц, API-префиксов и инфраструктурных объектов не меняются.

## Объём

- Детерминированный векторный логотип на основе выбранного знака: пузырь речи, звуковой импульс и строки публикации.
- Замена видимого бренда MediaHub на «Наговори» в публичной и авторизованной части.
- Favicon, Apple touch icon, PWA 192/512 px, maskable icon, metadata и manifest.
- Старт установленного PWA с `/app/notebook`.
- Нейтральный кэшируемый offline-shell блокнота без серверных заметок и персональных данных.
- Сохранение нового текста и аудио Blob в IndexedDB до любого сетевого запроса.
- Показ локальной очереди, состояния «сохранено на устройстве», ошибки и кнопки ручной синхронизации; автоматический foreground replay при возвращении связи.
- Удаление локального аудио только после подтверждённого создания заметки сервером.
- Необязательный клиентский UUID в API создания текста и atomic voice-create: повтор возвращает ту же `NotebookNote`, не создавая дубль.
- Service Worker остаётся GET-only: без Background Sync и без replay мутаций. Авторизованный React-клиент синхронизирует через существующие HttpOnly-cookie и CSRF.
- Проверка 390 и 1440 px, offline fallback, очереди текста/аудио, повторной синхронизации и защиты от дублей.

## Допущения

- Перед поездкой владелец один раз открывает `/app/notebook` после входа и при доступном интернете: это сохраняет workspace-контекст и обновляет Service Worker.
- Данные браузера не очищены, приватный режим не используется.
- Доступны IndexedDB и Service Worker; для голоса дополнительно нужны `MediaRecorder` и разрешение микрофона.
- OpenAI используется только после возвращения связи. Офлайн-запись токены не расходует.
- На iOS нельзя обещать надёжную фоновую работу. Синхронизация запускается в открытом приложении: при загрузке, событии `online` или по кнопке.

## API

- `POST /api/v1/notebook` принимает необязательный `client_note_id: UUID`.
- `POST /api/v1/notebook/transcribe-new` принимает необязательный `client_note_id: UUID`.
- Если такой ID уже принадлежит заметке указанного workspace, API возвращает существующую заметку без второго `NotebookNote`, транскрипции и usage event.
- Коллизия с другим workspace не раскрывает чужую запись.
- Без `client_note_id` сохраняется прежнее поведение.

## Данные и миграции

Миграции базы нет. Клиентский UUID используется как существующий primary key `notebook_notes.id`.

В IndexedDB хранятся workspace ID, UUID заметки, текст, необязательный аудио Blob/MIME, необязательный уже загруженный media ID, время, число попыток и безопасная ошибка. Токены авторизации и сторонние секреты не сохраняются.

## Проверки

- API: повтор создания текста с одним UUID даёт одну заметку.
- API: повтор atomic voice-create даёт одну заметку, одну транскрипцию и одно событие расхода.
- API: чужой workspace по UUID не раскрывается.
- Frontend: очередь переживает reload; успех удаляет запись, ошибка сохраняет Blob; media ID фиксируется до транскрипции.
- Service Worker: offline-shell в кэше, только GET, без Background Sync и mutation replay.
- Browser: логотип и блокнот без overflow на 390/1440 px.
- Browser: offline-навигация открывает сохранение, текст и тестовый звук остаются на устройстве, после связи создаётся одна заметка.
- Полные проверки: OpenAPI, lint, typecheck, focused/full tests, production build, visual/offline smoke и `git diff --check`.

## Риски

- Браузер может очистить storage: запрашиваем persistent storage, показываем очередь и предупреждаем не очищать данные до синхронизации.
- Связь пропала после загрузки: media ID сохраняется в IndexedDB до вызова STT.
- Ответ потерян после commit: повтор с тем же `client_note_id` возвращает существующую заметку.
- Две вкладки: локальный lock плюс серверная уникальность primary key.
- Утечка кэшированного HTML: авторизованный HTML не используется как offline fallback; кэшируется нейтральный shell.
- Старая установленная PWA: меняем имя кэша и набор manifest-иконок.

- Авторизованная production-проверка выявила расхождение server/client timezone в подписи времени заметки.

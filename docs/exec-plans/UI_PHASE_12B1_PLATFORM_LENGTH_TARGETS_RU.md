# Phase 12B.1: цели длины по площадкам

Статус: реализовано и проверено локально; production не изменён
Дата: 1 августа 2026
Область: существующий Voice First композер и существующие настройки проекта/рубрики; без новых верхнеуровневых экранов, публикации, деплоя и изменений production

## Цель

Добавить редактируемые версионируемые цели длины для Telegram, MAX, VK и Instagram на уровне проекта и необязательной рубрики. Пользователь может переопределить цель только для текущего материала, не меняя проект и рубрику. Приоритет:

`текущий материал -> рубрика -> проект -> системный профиль`.

Технические пределы коннекторов остаются неизменяемыми ограничениями безопасности и не выдаются за редакционные цели.

## Допущения и формат данных

- Миграция БД не нужна: `ProjectVersion.character_count_policy` и `RubricVersion.platform_overrides` уже являются версионируемыми JSON-полями.
- Цели проекта хранятся в `character_count_policy.platform_targets`.
- Цели рубрики хранятся в `platform_overrides.length_targets`.
- Разовые цели отправляются в запросе сборки версий и сохраняются snapshot в payload каждой версии площадки.
- Цель имеет форму `{min_chars, max_chars}`. В наследуемых настройках границы могут отсутствовать, но явный диапазон текущего материала должен быть положительным и `min_chars <= max_chars`.
- Максимальная цель MAX и Instagram не может превышать hard limit коннектора.

## Изменения API и приложения

1. Вернуть `character_count_policy` в `ProjectOut`, а `platform_overrides` в `RubricOut`.
2. Добавить в `GenerateVariantsRequest` словарь `length_overrides` по площадкам.
3. Добавить общий resolver: проверка, наследование, безопасное ограничение устаревших сохранённых целей hard limit и фиксация `source`, границ и hard limit.
4. Сохранять применённую цель в `PlatformVariant.payload.length_target`.
5. При повторной сборке той же мастер-ревизии с другой разовой целью создавать новую ревизию площадки, а не возвращать старый snapshot.
6. Добавить цели площадок в существующие формы правил проекта и рубрики.
7. Добавить в существующий композер компактную настройку `Длина этого поста`. Профили используют безопасные диапазоны; точную цель можно скопировать в Telegram, MAX и VK.
8. Если явная цель поста/рубрики/проекта не достигнута, один раз запускать существующий ИИ-редактор отдельно для этой площадки. Он работает с полным источником, сохраняет прошлую ревизию и сам не добавляет постоянный подвал.
9. На готовом результате показывать применённую цель, источник правила, фактическое количество и честное предупреждение, если диапазон всё ещё не достигнут.

## Проверки

- Unit-тесты наследования, неверных диапазонов и hard limit.
- API-тесты выдачи версионируемых настроек проекта и рубрики.
- Integration-тесты snapshot разовой цели и новой ревизии при её изменении без дублирования ContentItem.
- Typecheck и production build фронтенда.
- Browser smoke существующего композера на 390 px и 1440 px.

## Риски и защита

- В JSON уже могут быть другие ключи: вложенные объекты объединяются, а не заменяются.
- Постоянный подвал входит в технический предел: валидируется итоговый текст, а цель остаётся редакционным ориентиром.
- ИИ может не попасть точно в диапазон после одной попытки: нельзя запускать бесконечный цикл или молча обрезать текст. Интерфейс показывает факт и цель, оставляет редактирование и ручную пересборку.
- Разовые цели являются snapshot сборки и не меняют правила проекта/рубрики.

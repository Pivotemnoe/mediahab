# Phase 12B.3: read-only spike официального VK API

Проверено: 1 августа 2026 года
Решение: оставить VK в ручном режиме; не добавлять и не включать автоматический коннектор в Phase 12B.3

## Что подтверждают официальные источники

- Официальный репозиторий VK Java SDK сообщает, что SDK создаётся из VK API JSON Schema и сейчас ссылается на версию схемы API 5.199.
- Официальный пример публикации фото на стену состоит из нескольких шагов: получить upload server стены, загрузить файл, сохранить wall photo, собрать id вложения и затем вызвать `wall.post` с этим вложением.
- SDK описывает разные OAuth actor для пользователя и сообщества; нужны приложение, secret, redirect URI и отдельный authorization flow.
- В официальном issue tracker `VKCOM/vk-api-schema` остаётся открытым отчёт 2026 года: текстовый `wall.post` работает с community token, но `photos.getWallUploadServer` возвращает ошибку групповой авторизации 27. Это подтверждает текущую неоднозначность авторизации загрузки медиа, а не готовый стабильный контракт.

## Следствия

- Не хардкодить неподтверждённый предел текста в capability VK.
- Не считать публикацию текста и загрузку медиа одним API-вызовом.
- Перед автоматическим коннектором выполнить credentialed sandbox spike именно для подключаемого приложения и сообщества: actor авторизации, `wall.post`, загрузка/сохранение фото, видео, ссылки, редактирование/удаление, защита от дублей, rate limits и карта ошибок.
- Такой будущий spike передаёт данные и меняет внешний VK sandbox, поэтому потребует отдельного подтверждения владельца и тестовых credentials только в secret-конфигурации.

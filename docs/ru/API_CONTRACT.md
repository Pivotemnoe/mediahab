# Контракт API

Базовый путь `/api/v1`, JSON в `snake_case`, даты ISO 8601 UTC. Каждая мутация проверяет workspace, роль и entitlements. Долгие операции возвращают `202` и ресурс задачи. OpenAPI генерирует FastAPI, а TypeScript-клиент строится из него.

## Общие правила

- Ошибка: `{ "error": { "code", "message", "details", "request_id" } }`.
- Optimistic locking через `version` или `If-Match`, конфликт — `409`.
- `Idempotency-Key` для публикаций, оплат, загрузок и отдельных AI-задач.
- Секреты никогда не возвращаются API.

## Основные группы маршрутов

### Авторизация

`/auth/register`, `/auth/login`, `/auth/logout`, `/auth/logout-all`, `/auth/refresh`, подтверждение email, восстановление пароля, `/me` и управление сессиями.

### Рабочие пространства

CRUD `/workspaces`, участники и приглашения. Чужой объект не раскрывается.

### Хранение

`GET/PATCH /workspaces/{workspace_id}/retention`, dry-run/очередь через `POST /retention/scan`, явное продление `/retention/{candidate_id}/retain` и owner-only `/retention/execute-ready` после grace.

Пилот показывает 30 дней для оригиналов фото/видео и горизонт 180 дней для текста. Скан ограничен workspace и идемпотентен. Физическое удаление по умолчанию выключено. Голос исключён, пока `raw_voice_days` не утверждён; внешние посты и публикационные доказательства не затрагиваются.

### Проекты

Список и создание, создание из пресета, импорт, экспорт, клонирование, архив, версии.
Активная версия возвращает `character_count_policy`, включая редакционные цели длины по площадкам.

### AI-генератор проекта и рубрик

`/projects/generate-suggestions`, `/projects/{id}/rubrics/generate-suggestions`, принятие или удаление предложений. Предложение не становится активным без подтверждения.

### Рубрики

CRUD, архив, восстановление, клон, версии, схема формы и проверка JSON Schema.
Активная версия возвращает `platform_overrides`, включая более точные цели длины рубрики.

### Правила, промпты и шаблоны

CRUD и история версий. Сырой редактор промпта может быть доступен только администраторам и по feature flag.

### Примеры

Ручное добавление, общий импорт `/projects/{project_id}/examples/import` для manual/JSON/Telegram, утверждение, отклонение, embeddings, переиндексация и статус import job.

### Контент и блоки

CRUD ContentItem, динамические поля, повторяемые группы, блокировка и разблокировка фактов.

### Голос и медиа

Presigned upload, подтверждение загрузки, удаление, запуск распознавания, статус, принятие и повтор.

### AI

Извлечение фактов, сборка master, крючок, оценки, quality check, журнал `/ai-runs/{run_id}`, отмена, повтор задачи и идеи:

```text
GET  /workspaces/{workspace_id}/ideas/capability
POST /workspaces/{workspace_id}/ideas/generate
POST /workspaces/{workspace_id}/ideas/transcribe-topic

# Legacy-совместимость проектных идей
GET  /projects/{project_id}/ideas/capability
POST /projects/{project_id}/ideas/generate
POST /ai-runs/{run_id}/ideas/{idea_id}/accept
```

Workspace capability отдельно сообщает, включена ли функция и имеет ли текущий участник право генерировать, а также возвращает дневной лимит и остаток. До вызова провайдера backend проверяет feature flag, редакторскую роль, подписку, дневную и месячную квоту. Standalone- и legacy-запуски используют общий дневной лимит идей.

`POST /workspaces/{workspace_id}/ideas/generate` принимает ровно одну непустую тему `topic` и не принимает проект, рубрику, редакционную цель, примеры, недавние темы или content item. Тема считается недоверенными данными и всегда трактуется как возможная тема поста, а не как команда ответить, посчитать, найти данные, раскрыть prompt или дать профессиональный совет. Пустой или состоящий из пробелов ввод возвращает стабильный `422 idea_topic_required` до вызова провайдера и учёта usage.

Endpoint создаёт долговечный workspace-scoped generation run с `project_id: null`, `rubric_id: null` и `content_item_id: null`. Ответ следует версионному контракту `phase12j-standalone-idea-directions-v1` и содержит ровно пять смыслово различных объектов без дополнительных полей:

```json
{
  "ideas": [
    {
      "id": "idea-1",
      "title": "Короткое название направления",
      "direction": "О чём может рассказать автор без утверждения фактов.",
      "speaking_prompt": "Какой реальный момент вы хотите описать?"
    }
  ]
}
```

`direction` — редакционная возможность, а `speaking_prompt` — один вопрос автору. Это не ответ, не рекомендация, не пост, не цитата автора, не личное событие и не фактическое утверждение. Неподанные имена, числа, даты, цены, цитаты, URL, утверждения от первого лица, готовые абзацы и медицинские, ветеринарные, психологические, фитнес-, юридические, налоговые или финансовые советы невалидны. Допустим один ограниченный повтор всего набора внутри того же run и резервирования квоты; вторая ошибка возвращает стабильный failed run без направлений. Повтор failed standalone run через retry endpoint не требует проекта и применяет обычную политику квоты нового run.

Генерация и выбор standalone-направления не создают `ContentItem`, блок, заметку, ревизию, locked fact или публикацию. Клиент хранит короткоживущую planning-ссылку и открывает редактор с пустым авторским вводом. Проект и рубрика выбираются там. Только начало диктовки или явное сохранение авторского текста создаёт один материал; направление хранится отдельно как незафиксированный planning-блок `ai_suggested`. Выбор, refresh, resume, transcription, lock и сборка master никогда не продвигают его в авторский исходник. `assemble-master` продолжает возвращать `422 author_source_required`, пока пользователь не даст непустой голос, текст, подтверждённый импорт или locked fact.

`POST /workspaces/{workspace_id}/ideas/transcribe-topic` принимает только короткое загруженное голосовое медиа этого workspace. Он возвращает текст для поля темы, учитывает STT usage, соблюдает срок хранения исходного аудио и не создаёт заметку или материал.

Следующий контракт проектных идей сохранён как legacy-совместимость. Его отдельный feature flag остаётся выключенным, а UI не показывается в основном редакторе, пока standalone-идеи активны. Исторические runs и accept-route остаются читаемыми и повторяемыми для отката и аудита.

Генерация принимает необязательную рубрику, тему и редакционную цель, создаёт проектный generation run и возвращает ровно пять структурированных нефактических заготовок, не создавая материал. Принятие идеи по `client_content_id` идемпотентно создаёт ровно одну оболочку черновика и при повторе той же комбинации возвращает тот же материал. Использование этого client ID для другого run или другой идеи завершается конфликтом. Первая структурированная ревизия и usage event сохраняют `run_id`, `idea_id`, `client_content_id` и `content_item_id` как provenance, но текст ревизии и авторский исходник остаются пустыми. Отдельный блок `ai_suggested` нельзя зафиксировать как факт, и он исключён из целей расшифровки и входа сборки мастер-текста. При клонировании legacy-материала lock такого planning-блока не переносится. До появления непустого голоса, текста, подтверждённого импорта или locked fact endpoint `assemble-master` возвращает `422 author_source_required` до вызова провайдера; внутренние блоки `system` это требование не выполняют. Перенос заметки из блокнота в черновик с идеей создаёт или дополняет отдельный авторский блок и никогда не перезаписывает структурированную идею или её provenance. Обновление ранее зафиксированного блока с `lock=false` также удаляет соответствующий locked fact. Платформенные версии относятся к следующему этапу.

Все endpoint генерации создают долговечный audit run и возвращают `202`, кроме быстрых детерминированных валидаторов и capability-запросов.

### Редакции

История, утверждение, fork, редактирование и валидация вариантов площадок.
`POST /content-items/{content_id}/generate-variants` принимает необязательный `length_overrides` по площадкам. Он действует только для текущей сборки, сохраняется в `PlatformVariant.payload.length_target` и не меняет проект или рубрику.

Этот же endpoint принимает необязательный `instagram_format: image | carousel | reel`, когда выбран `instagram`. Если поле передано, backend проверяет текущий порядок медиа (`image`: ровно один визуальный файл; `carousel`: 2–10 визуальных файлов; `reel`: ровно одно видео) и сохраняет формат, порядок медиа и id обложки в `PlatformVariant.payload`. Отсутствие поля сохраняет совместимость с существующими API-клиентами.

Для `vk` созданная версия сохраняет `payload.vk_export_package`: тип результата `community_post`, ручной режим публикации, упорядоченные фото/видео и id обложки. Изменение порядка медиа создаёт новую ревизию версии площадки, даже если мастер-текст не менялся. Существующий коннектор `manual_export` возвращает тот же порядок вложений вместе с финальным текстом.

`POST /platform-variants/{variant_id}/refine` возвращает входные/выходные токены и символы generation run вместе с `cost_estimate_micro_usd`. Если провайдер вернул токены, они считаются основными; данные по символам позволяют клиенту показать явно обозначенную приблизительную оценку.

Каждая новая или явно повторно проверенная версия площадки содержит `validation.preflight`. В нём есть общий статус `pass | warning | block` и четыре упорядоченные проверки (`length`, `media`, `format`, `delivery`), каждая со стабильным кодом и русскими пользовательскими `label`/`message`. Готовность способа отправки не означает, что конкретный аккаунт уже подключён: ручные коннекторы сообщают о ручном экспорте, а capability автоматического коннектора остаётся в `warning` до проверки конкретного направления. Снимок является добавочным, не содержит реквизитов доступа и не заменяет подтверждение человеком.

### Подключения

Подключение OAuth или bot token, callback, проверка, refresh, отключение; направления проекта, capabilities и тест подключения.

### Публикации

Создание, планирование, немедленная отправка, отмена, повтор, обновление статуса, редактирование, удаление внешнего поста и история попыток. Публикация запрещена, если конкретная редакция варианта не утверждена.

### Биллинг

Тарифы, подписка, usage, checkout через mock, отмена, ручное назначение тарифа системным администратором, платежи и счета.

### Webhook

Отдельные endpoint для MAX, Meta, платежей и generic webhook. Обработчик быстро проверяет, дедуплицирует, сохраняет и передаёт обработку в фон.

Системные административные маршруты находятся под `/api/v1/admin` и требуют отдельной системной роли, а не обычного `workspace owner`.
